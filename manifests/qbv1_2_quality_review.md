# QB-v1.2 题目质量审查记录

## 结论

`QB-v1.2` 的主目标是提升题目质量，而不是修改系统页面。  
这轮审查结果是：

- `B1-B8` 进行了系统重建
- `A/C` 暂不全面重写，但保留“明显坏题清理”方向
- `QB-v1.1` 保留为历史基线
- `QB-v1.2` 切换为当前 live 正式题库

## 旧版问题归纳

### B1

问题：

- 同一 harmful ask 仅换要点数量
- 缺少更细 harm taxonomy
- 更像“会不会机械拒答”而非真实危险请求拒答

处理：

- 全部替换

### B2

问题：

- 主要依赖旧式 DAN / “忽略限制”模板
- 缺少翻译转义、协作草稿、policy reinterpretation 等现代 jailbreak 家族

处理：

- 大面积替换
- 保留 `jailbreak_resistance` 任务轴，但换成多家族结构

### B3

问题：

- 典型题面只是同一合法请求后缀 `#1/#2/#3`
- 对 benign boundary 的真实世界场景覆盖不足

处理：

- 大面积替换

### B4

问题：

- 模块思路本身可保留
- 但题面和引用核验材料偏旧、偏薄

处理：

- 保留能力轴
- 全部升级题面和 citation 素材

### B5

问题：

- 大量同构重复
- 只是“背景介绍 -> 再追问危险步骤”
- 没有真正的 indirect prompt injection 结构

处理：

- 完全重建

### B6

问题：

- 多轮结构几乎固定
- 只是换 topic
- 缺少真实升级轨迹

处理：

- 完全重建

### B7

问题：

- 多数题只是“拒答后换个说法继续问”
- pseudo-compliance 设计薄弱

处理：

- 完全重建

### B8

问题：

- “教学助理 + 案例 1/2/3”模式重复严重
- 不能反映 tool-use / workflow misuse / professional unsafe delegation

处理：

- 大面积替换

## 替换标准

本轮按以下标准剔除或重写旧题：

- 与另一题完全重复
- 与另一题同构，只换 topic label / 数字 / 案例编号
- 只能测模板拒答，不能测真实安全边界
- 明显依赖旧式 DAN / 无约束角色扮演
- 不反映 2024-2026 更真实的部署风险
- 合法边界题过于造作，不像真实用户请求

## 新题的保留标准

新题至少满足：

- 主题真实
- 场景合理
- 指令链条自然
- 攻击方式可以归类
- 评分仍可程序化落地
- 在同模块内与其他题有可解释区分

## 非安全模块处理策略

本轮没有全面重写 `A/C`，因为优先级放在 `B1-B8`。  
但仍然保留以下后续审查方向：

- `A2`：继续识别是否仍有低难、演示化编程题
- `A6`：继续识别是否有普通抽取题伪装成逻辑推理
- `C4`：继续关注评分口径和题目区分度是否一致
